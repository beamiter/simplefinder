1. INTRODUCTION                                           *simplefinder-intro*

SimpleFinder is a lightweight project finder for Vim 9. Vim9 script drives a
native side panel; a resident Rust daemon does parallel file scanning, fuzzy
ranking (nucleo) and full-text search (ripgrep libraries). They talk over
stdin/stdout with one JSON message per line.

Grep results stream: the panel paints the first matches while the walk is
still running and says `12 results · searching…` until it ends, rather than
showing nothing until the last file has been read. Each batch is a complete,
correctly ordered snapshot rather than an append, so rows never reshuffle at
the end; a match found late can still sort in above the row you are on, so the
cursor follows the row it was on rather than its position, and that row keeps
its place on screen instead of the panel scrolling back to the top. Streaming is
negotiated (protocol v4, `stream` capability), so a daemon built before this
version keeps replying once per search. |:SimpleFinderFiles| does not stream:
its ranking needs the whole file list before anything can be ordered.

Grep does not walk the tree for every keystroke. The daemon keeps the file list
it built for |:SimpleFinderFiles| for 30 seconds, and a grep whose filters match
that list reads it instead of walking again — no directory stat-ed twice, no
ignore file re-read — while a grep that does have to walk publishes its own list
so the next keystroke can skip it. The trade is that a file created while a
panel is open is not searched until the list expires; set
|g:simplefinder_grep_cache| to 0 to walk every time. This is negotiated too
(`grep_cache` capability), so an older daemon keeps walking.

The first search of a session is the one that starts the daemon, so it is
raised before that negotiation has finished. It waits for the handshake (up to
two seconds) and then goes out knowing what the daemon can do, instead of
asking for the lowest common denominator on the one search guaranteed to be
slow — nothing is cached yet. The same applies after |:SimpleFinderRestart| and
after a crash restart. A daemon that never answers still gets the search, which
then behaves as it did before streaming existed. A search still waiting when
the daemon goes away is dropped rather than re-sent: re-sending it runs through
the code that starts the daemon, and stopping one is an instruction, not a
pause.

Requires Vim 9.0+ with |+job|, |+channel|, |+timers|, |+textprop| and
|+popupwin|. Run ./install.sh once to compile the daemon (Rust 1.88+).

2. COMMANDS                                            *simplefinder-commands*

                                                          *:SimpleFinderFiles*
:SimpleFinderFiles [query]   Fuzzy-find project files.
                             Honours |g:simplefinder_include_globs| and
                             |g:simplefinder_exclude_globs|.

                                                           *:SimpleFinderGrep*
:SimpleFinderGrep [text]     Grep project text (prompts if no argument).
                             Path globs are applied before files are read.

                                                          *:SimpleFinderIGrep*
:SimpleFinderIGrep [text]    Live grep: results update as you type.
                             Uses the same path globs as regular grep.

                                                       *:SimpleFinderGrepWord*
:SimpleFinderGrepWord        Live grep for the word under the cursor.

                                                     *:SimpleFinderGrepVisual*
:SimpleFinderGrepVisual      Live grep for the Visual selection. Charwise,
                             linewise and blockwise all work; multiple lines
                             are joined with a space.
                             Invoked while Visual mode is still active (the
                             |<Plug>| mapping below) it reads the *current*
                             selection; invoked as :'<,'>SimpleFinderGrepVisual
                             there is no live selection left, so it reads the
                             |'<| and |'>| marks instead.
                             Map it with |<Plug>(simplefinder-grep-visual)|,
                             not by hand -- see |simplefinder-mappings|.

                                                        *:SimpleFinderBuffers*
:SimpleFinderBuffers         Fuzzy-find open buffers (most recent first).

                                                         *:SimpleFinderRecent*
:SimpleFinderRecent          Fuzzy-find recently used files.

                                                        *:SimpleFinderSymbols*
:SimpleFinderSymbols [query]
                             Search the project for definitions. Matches lines
                             that begin a definition -- fn, struct, def, class,
                             func, interface and so on -- using the keyword set
                             for the current buffer's filetype, then narrows by
                             [query]. Typing continues to narrow live.

                             There is no tags file or language server behind
                             this: it runs on the same grep the daemon already
                             provides, so it needs no setup, never goes stale
                             against the files on disk, and searches a large
                             repository in a few milliseconds. It is coarser
                             than a real index -- it finds where a name is
                             defined, not what it resolves to.

                             |g:simplefinder_symbol_keywords| overrides the
                             keyword set for a filetype;
                             |g:simplefinder_symbol_all_languages| searches
                             every language at once, which is usually what a
                             polyglot repository wants.
                             Path include/exclude globs apply to this source
                             because it shares the daemon grep traversal.

                                                       *:SimpleFinderGitFiles*
:SimpleFinderGitFiles        Fuzzy-find files in the current git repository.
                             Reads the index with `git ls-files` instead of
                             walking the tree, so it stays fast in very large
                             repositories and already honours .gitignore,
                             sparse checkouts and skip-worktree. Untracked
                             files that are not ignored are included, so a
                             file you just created is findable before it is
                             staged. Paths resolve against the repository
                             root, which may differ from |:SimpleFinderRoot|.
                             Reports an error outside a repository.

                                                          *:SimpleFinderLines*
:SimpleFinderLines           Fuzzy-find lines in the current buffer; <CR>
                             jumps to the line (works for unnamed buffers
                             too). The preview popup centers on the line.

                                                           *:SimpleFinderHelp*
:SimpleFinderHelp            Fuzzy-find help tags from all of 'runtimepath'
                             and open the selection with :help.

                                                         *:SimpleFinderResume*
:SimpleFinderResume          Re-open the last search: same mode, query and
                             option toggles.

                                                          *:SimpleFinderMarks*
:SimpleFinderMarks           Fuzzy-find marks: this buffer's a-z first, then
                             the file marks A-Z and 0-9. Rows show the mark,
                             the file, the line number and, when the file is
                             already loaded, the line itself. Automatic marks
                             ('. '^ '" '< '>) are left out -- nobody set them.

                                                          *:SimpleFinderJumps*
:SimpleFinderJumps           Fuzzy-find the jump list, most recent first.

                                                       *:SimpleFinderQuickfix*
:SimpleFinderQuickfix        Fuzzy-find inside the current quickfix list. A
                             400-entry list from a project-wide grep is what
                             |:cnext| is worst at.

                                                        *:SimpleFinderLoclist*
:SimpleFinderLoclist         The same for the current window's location list.

                                                           *:SimpleFinderRoot*
:SimpleFinderRoot [dir]      Show, or pin, the search root directory.
                             With an active SimpleRemote workspace, {dir}
                             changes that remote workspace root instead
                             (or, with SimpleRemote's tree-root sync off,
                             the tree root searches follow; see
                             |simplefinder-remote-root|).

                                               *:SimpleFinderRemoteWorkspaces*
:SimpleFinderRemoteWorkspaces
                             Fuzzy-find SimpleRemote workspaces: the recent
                             ones first (g:SimpleRemoteRecentWorkspaces()),
                             then the configured profiles
                             (g:SimpleRemoteProfiles()) that are not already
                             among them, each listed once by kind, target
                             and root. Rows read `kind:target root`, with
                             the profile name in front when it has one, the
                             local projection after `->` when it has one,
                             and `(profile)` for a profile; the workspace
                             connected right now is marked with `*`. <CR>
                             hands the row to g:SimpleRemoteOpenWorkspace(),
                             which connects and opens its tree; a profile
                             without a root prompts for one there. Works
                             with no workspace open -- it is how you get to
                             one -- and does not need |g:simplefinder_remote|.
                             Reports an error without SimpleRemote.

SIMPLEREMOTE INTEGRATION                              *simplefinder-remote*

An active g:simpleremote_workspace becomes the project automatically. Which
engine searches it depends on the workspace mode:

  virtual        Files, Grep, IGrep, GrepWord, GrepVisual, Symbols and
                 GitFiles run on the remote host through
                 g:SimpleRemoteShellCommand(). Results open as remote://
                 buffers and previews use g:SimpleRemoteReadFile()
                 asynchronously.
  sshfs          The mount is a FUSE filesystem, and a local daemon walking
                 it reads every file over SSH one syscall at a time. So the
                 search runs on the host exactly as for a virtual workspace,
                 and its results resolve to plain local paths under
                 local_root: they open, split and preview as ordinary
                 files, and the quickfix list holds local names. Set
                 |g:simplefinder_remote_search_projected| to 0 to walk the
                 mount with the local daemon instead. While the mount is
                 still coming up (mode `mounting`) the search already runs
                 on the host; when SimpleRemote publishes the mount, the
                 listing in flight is kept and its results simply resolve
                 to the mount from then on.
  docker-bind, local-map
                 Real local directories; the ordinary local daemon searches
                 local_root.

The transport kind (ssh, docker, or anything SimpleRemote adds later) is not
inspected: everything crosses through SimpleRemote's functions, so a kind
this plugin has never heard of works like ssh. The panel title shows
`[kind:target]` whenever a search runs through the transport.

When `rg` exists remotely it supplies ignore, hidden, and path-glob semantics.
Without it, file search falls back to Git/find and text search to grep. File
names are enumerated across the transport and fuzzy-filtered locally, so each
keystroke does not start a new SSH traversal. Grep requests are cancellable
and paint results asynchronously.

Buffers and recent files~
|:SimpleFinderBuffers| lists open remote:// buffers (SimpleRemote gives them
'buftype' acwrite so saves go through its BufWriteCmd; no other 'buftype' is
listed) by their full remote:// name, marked `[remote]`. |:SimpleFinderRecent|
records remote:// buffers when they are entered and when SimpleRemote reports
that their asynchronous fill landed (User SimpleRemoteBufferRead), keeps
remote:// entries from 'viminfo' without a filereadable() check, and, while a
workspace is active, lists that workspace's files first, in their own recency
order, ahead of everything else. Both open through SimpleRemote's remote://
boundary.

Events~
The finder follows SimpleRemote's User events (see the SimpleRemote help):
SimpleRemoteConnected and SimpleRemoteWorkspaceChanged re-snapshot the
workspace and re-run an open Files/Grep/Symbols/GitFiles panel against the
new root; SimpleRemoteDisconnected with reason 'disconnect' (or any reason
but 'reconnect') reports `remote workspace disconnected` and the panel
resumes when the workspace comes back. A workspace switch -- SimpleRemote
fires Disconnected with reason 'reconnect', then SimpleRemoteConnecting, then
Connected, with no workspace published in between -- is not a disconnection:
the panel keeps the old host in its title, says `searching…`, and a search
typed during the gap waits for Connected too, which re-dispatches it. A
panel opened during the gap follows the connection being replaced the same
way rather than searching the local cwd, and |:SimpleFinderRoot| {dir}
refuses to pin a local root until the switch is over. A switch can also be
abandoned: SimpleRemote emits Disconnected before it starts the new
transport, and a transport that fails to start (no ssh or docker binary, a
target it refuses) leaves no further event, so the Connected that would end
the switch never arrives. `g:simpleremote_status` tells the two apart -- a
switch in flight is `connecting kind:target`, an abandoned one is back to
`disconnected` -- and the finder reads it on the way to every question the
switch would otherwise hold up: the panel reports `remote workspace
disconnected` once, and the next search and |:SimpleFinderRoot| are local
again. A WorkspaceChanged or SimpleRemoteTreeRootChanged that changes
nothing a running search depends on (same connection, same search directory,
same engine) leaves that search running rather than restarting it.

                                                   *simplefinder-remote-root*
Root~
|:SimpleFinderRoot| {dir} goes the other direction and asks SimpleRemote to
change its workspace root through g:SimpleRemoteTreeSetRoot(). What that
does depends on SimpleRemote's g:simpleremote_sync_tree_root:

  on (SimpleRemote's default)
        The workspace itself moves: SimpleRemote reconnects there and the
        Connected event brings the finder along. Its `tree_root` then only
        differs from `root` during a view-only reveal, which the finder
        ignores -- a reveal must not narrow a search.
  off   Nothing reconnects; only the tree's view root (`tree_root`) moves and
        SimpleRemoteTreeRootChanged fires. Searches follow it: the remote
        script enters the subdirectory, results are relative to it and
        resolve back to absolute paths (remote:// or under the mount), and
        the message says `remote search root: {dir} (workspace root {root})`.
        A tree root outside the workspace is not followed, because
        SimpleRemote refuses to read files outside its root; the message
        says so and searches stay in the workspace root. This applies to the
        remote tree's own re-rooting keys as well as to |:SimpleFinderRoot|.

Set |g:simplefinder_remote| to 0 to stop following the workspace: searches
and project-root detection stay local. It is read every time a panel resolves
which workspace to search, so switching it off at runtime takes effect on the
next panel rather than at the next restart -- and a connect or reconnect
arriving afterwards does not revive the workspace the finder was following.

Two things are not workspace-following and stay. One is
|:SimpleFinderRemoteWorkspaces|, which opens a workspace rather than
searching one. The other is the remote:// buffers that are already open,
which |:SimpleFinderBuffers| and |:SimpleFinderRecent| go on listing -- an
open buffer is an open buffer whatever this option says, and dropping it from
those two lists would only hide a file the user has in front of them.

|:SimpleFinderHealth| names the active workspace, its mode, which engine
searches it and where, the SimpleRemote runtime and protocol in use, and
whether the SimpleRemote functions this plugin calls are present -- or, with
no workspace, why there is none. It also reports whether
|:SimpleFinderRemoteWorkspaces| has the API it needs, because with no
workspace that is the way to get one. With no workspace and none of that API
defined there is no SimpleRemote installed at all, and the report says
nothing about the picker rather than naming three functions the reader has
never heard of.

3. PANEL KEYS                                              *simplefinder-keys*

Navigation and opening~
  <CR>            open the selected result
  <C-v> / <C-x>   open in vertical / horizontal split
  <C-t>           open in a new tab
  <C-j> <C-n> <Down>   next result
  <C-k> <C-p> <Up>     previous result
  <Esc> <C-c>     close the panel

Multi-select and quickfix/location lists~
  <Tab>           toggle mark on the current result, then move down
  <S-Tab>         toggle mark, then move up
  <C-q>           send marked results (or all, when none are marked) to the
                  quickfix list and open it
  <C-l>           send the same ordered selection to the location list owned
                  by the exact window and buffer that launched the panel

                  If that source split was closed, changed buffers, or is now
                  in another tab from the panel, the panel remains focused
                  and reports an error; SimpleFinder never writes or opens
                  the list in a replacement context.

Marks use stable result identities, not screen indices. Query refinement,
option changes, and asynchronous result reordering therefore cannot move a
mark onto an unrelated row. A marked row hidden by the current query keeps a
complete snapshot and is exported in first-mark order. Unmarking discards that
snapshot; closing the panel clears the selection, so |:SimpleFinderResume|
never restores invisible old marks.

Query editing~
  <BS> <C-h>      delete the character before the cursor
  <C-u>           clear the query
  <C-w>           delete the word before the cursor
  <Left> <Right>  move the query cursor one character
  <Home> <End>    move to the start / end of the query
  <C-y>{reg}      paste a register into the query at the cursor
  <C-f>           edit the query on Vim's command line
  <C-Up>          recall an older query for this source
  <C-Down>        walk back towards the query you were editing

The block glyph in the prompt line is the query cursor: typing, <BS> and <C-w>
all act there, so a typo in the middle of a long pattern no longer costs
everything after it.

The panel reads keystrokes with one mapping per printable ASCII character, so
*typing* into it is limited to ASCII. Text that cannot be typed still reaches
the query two ways. <C-y> followed by a register name splices that register in
at the cursor -- a yanked identifier, path or error message, whatever its
script -- joining a multi-line register with spaces. <C-f> hands the query to
the real command line for a single edit, which brings every input method with
it; leaving that command line with <Esc> keeps the query as it was.

                                             *g:simplefinder_history_max*
Each source keeps its own list of queries actually searched for, most recent
first, recalled with <C-Up> and <C-Down>. |:SimpleFinderGrep| and
|:SimpleFinderIGrep| share one list, since they are the same search; a file
path fragment and a grep pattern are not interchangeable, so nothing else
does. <C-Down> past the newest entry restores the query recall started from.
g:simplefinder_history_max (default 50) caps each list. The history lives in
the running Vim only -- it is not written to disk and does not survive a
restart.

Search options (grep modes)~
  <C-r>           toggle literal text / regex     flag: [txt] / [.*]
  <C-a>           cycle case mode                 flag: [sC] / [aa] / [Aa]
                  smart: case-insensitive unless the query contains an
                  uppercase letter

All modes~
  <C-o>           toggle hidden files             flag: [hidden]
  <C-g>           toggle ignore files             flag: [all]
  <C-e>           toggle the preview popup
  <PageDown>      scroll the preview down half a screen
  <PageUp>        scroll the preview up half a screen

                                                        *simplefinder-preview*
The preview reads from the *buffer* whenever the file is loaded in one, so a
result in a buffer with unsaved edits previews the text the result was found
in rather than what is still on disk. A file that is not open is read once and
kept, so moving back and forth between results in it costs one read;
g:simplefinder_preview_cache (default 4) is how many such files are kept.
It is highlighted with the loaded buffer's 'filetype', or one derived from the
extension -- set g:simplefinder_preview_syntax to 0 to switch that off.
Scrolling is relative to the match being previewed and starts over whenever
another result is selected. g:simplefinder_preview_width (default 0 = fill the
columns beside the panel) caps the popup width, and
g:simplefinder_preview_max_bytes (default 2097152) is the size above which a
file is not read at all; buffers are exempt, being already in memory.

A popup belongs to the tabpage it was created in, and the preview is sized from
the panel window. Results arriving while you are in another tab therefore
repaint the panel but not the preview, which would otherwise have to be drawn
over whatever you are editing there; it comes back when you return to the
panel.

Buffers mode~
  <C-d>           delete (:bdelete) the selected buffer

4. CONFIGURATION                                         *simplefinder-config*

Set before the plugin loads; defaults shown. >

  g:simplefinder_max_results = 200       max results per query
  g:simplefinder_threads = 0             daemon worker threads (0 = per core)
  g:simplefinder_grep_cache = 1          grep reuses a recent file walk
  g:simplefinder_debounce_ms = 50        input debounce
  g:simplefinder_panel_width = 50        panel width in columns
  g:simplefinder_position = 'right'      'left' or 'right'
  g:simplefinder_close_on_select = 1     close panel after opening a result
  g:simplefinder_preview = 1             preview popup on by default
  g:simplefinder_preview_syntax = 1      highlight the preview
  g:simplefinder_preview_width = 0       preview width (0 = all that is free)
  g:simplefinder_preview_max_bytes = 2097152   largest file read for preview
  g:simplefinder_preview_cache = 4       files kept from previous previews
  g:simplefinder_remote = 1              follow the active SimpleRemote workspace
  g:simplefinder_remote_search_projected = 1
                                         search sshfs mounts on the host
  g:simplefinder_hidden = 0              include hidden files
  g:simplefinder_no_ignore = 0           ignore the ignore files
  g:simplefinder_regex = 0               grep starts in regex mode
  g:simplefinder_smart_case = 1          smart case for grep
  g:simplefinder_ignore_case = 0         force case-insensitive grep
  g:simplefinder_recent_files_max = 100  recent file list size
  g:simplefinder_history_max = 50        queries kept per source, this session
  g:simplefinder_lines_max = 50000       buffer lines :SimpleFinderLines reads
  g:simplefinder_root = ''               pin the search root ('' = auto)
  g:simplefinder_root_markers = ['.git', 'Cargo.toml', 'package.json',
                                 'go.mod', 'CMakeLists.txt', 'Makefile',
                                 '.project_root']
  g:simplefinder_include_globs = []      native include path globs
  g:simplefinder_exclude_globs = []      native exclude path globs
  g:simplefinder_daemon_path = ''        daemon binary override
  g:simplefinder_debug = 0               log daemon chatter with :echom
<
The project root is found by walking up from the current file looking for a
root marker, falling back to |getcwd()|. Scanning honours `.ignore`,
`.gitignore`, the global git ignore and `.git/info/exclude`. An enabled active
SimpleRemote workspace takes precedence; see |simplefinder-remote|.

                                                *g:simplefinder_remote*
g:simplefinder_remote
        Boolean, default 1. Follow an active SimpleRemote workspace. Set to 0
        to keep project-root detection and every search local; it is read
        whenever a panel resolves the workspace to search, so changing it at
        runtime takes effect on the next panel, not only at startup
        (|:SimpleFinderRemoteWorkspaces| still works: it opens workspaces
        rather than searching one, and open remote:// buffers stay in
        |:SimpleFinderBuffers| and |:SimpleFinderRecent|).

                                *g:simplefinder_remote_search_projected*
g:simplefinder_remote_search_projected
        Boolean, default 1. Search an sshfs-projected workspace on the host
        through the SimpleRemote transport, with results resolved to local
        paths under the mount, rather than walking the FUSE mount with the
        local daemon. Set to 0 to treat sshfs like docker-bind and local-map
        and use the local daemon. Virtual workspaces always use the
        transport; other projections always use the local daemon. See
        |simplefinder-remote|.

VALIDATION                                           *simplefinder-validation*

Every option above is read through |get()| with its default as the fallback,
which makes a misspelled name the one failure with no symptom at all: the
setting is never read, the default is used, and nothing says so. The whole set
of names is therefore declared once inside the plugin and checked against what
you actually set.

                                                *simplefinder#ValidateConfig()*
simplefinder#ValidateConfig()
        Returns a list of `[LEVEL] fact -- remedy` lines describing everything
        wrong with the configuration as it stands right now, empty when there
        is nothing to say. It never throws and never changes anything.

        [ERROR] means the value cannot be used as written: the name is not an
        option, the type is wrong, or the value names something that is not
        there. [WARN] means it is used, but not as written -- a value below a
        floor the plugin clamps, or a setting another setting overrides.

The same list is the CONFIG section of |:SimpleFinderHealth|. The [ERROR]
lines are additionally echoed once per session, after the first panel opens,
because a setting that will never do anything should not wait to be found by
someone who thought to run a health check. [WARN] lines stay in the report.

What is checked:

- The type of every option, including that `g:simplefinder_position` is
  "left" or "right". Flags accept |v:true| and |v:false| as well as 1 and 0.
- Numeric floors, reported with what the plugin does instead where it clamps
  -- a note in brackets below is exactly what makes that floor a [WARN] rather
  than an [ERROR]:
  `max_results` 1, `threads` 0 (one worker per core below that),
  `debounce_ms` 0 (below it the search fires as soon as the timer can run),
  `panel_width` 24 (the panel opens at 24 columns),
  `preview_width` 0 (below it the preview picks its own width), and 30 for any
  non-zero width (the preview opens at 30), `preview_max_bytes` 0 (below it no
  size limit is applied), `preview_cache` 1 (one file is always kept),
  `recent_files_max` 1 (below it the list is not trimmed), `history_max` 0
  (below it no query is remembered), `lines_max` 1 (below it only the first
  line is listed).
  `max_results` is the one floor with no such note, and that is deliberate:
  there is no behaviour to describe, because an empty query takes that many
  paths off the front of the list, so 0 lists nothing at all.
- That `g:simplefinder_root_markers`, `g:simplefinder_include_globs` and
  `g:simplefinder_exclude_globs` hold only non-empty strings, and that no glob
  starts with `!` -- |g:simplefinder_include_globs| rejects those, rather than
  guess which way you meant to invert the filter.
- That `g:simplefinder_symbol_keywords` maps a filetype to a list of non-empty
  strings; a value that is not a list leaves the built-in keywords in place.
- That `g:simplefinder_root`, when set, is a directory, and that
  `g:simplefinder_daemon_path`, when set, is executable.
- That `g:simplefinder_ignore_case` and `g:simplefinder_smart_case` are not
  both on, since the first one wins.
- Any other `g:simplefinder_` name, which is a typo by definition.
  `g:loaded_simplefinder` and a plain `g:simplefinder` are left alone.

					*g:simplefinder_max_results*
g:simplefinder_max_results
	How many results one query returns. Default 200.

	A grep that finds more keeps the first g:simplefinder_max_results of
	the (path, line, column) order -- the same results a full sort would
	have put first -- so a query that scans the whole tree returns the same
	set every time and <C-q> exports the same quickfix list. The panel then
	reports both numbers, e.g. `200/5312 results`, rather than only how
	many fit.

	Counting is what makes that total honest, so the daemon keeps scanning
	past the cap. It stops at 50x g:simplefinder_max_results matches (at
	least 10000), which a normal search is nowhere near but `.` as a regex
	over a monorepo reaches immediately. Stopping ends the walk itself, so
	past that point neither number is complete: the total is a lower bound,
	and the kept results are the first ones out of whichever files the walk
	had reached -- which files those are depends on how the walker's
	threads were scheduled, so two runs of the same query can return
	different sets and <C-q> can export different lists. The panel marks
	exactly this with a trailing +: `200/10000+ results`. Narrow the
	pattern (or raise g:simplefinder_max_results, which raises the ceiling
	with it) to get a complete scan and a stable set back.

					     *g:simplefinder_threads*
g:simplefinder_threads
	How many worker threads the daemon uses for the file walk and for
	fuzzy scoring. Default 0, meaning one per core.

	Scoring is per candidate and independent, so the file list is split
	across these threads and the partial rankings merged before the single
	sort that decides the order -- the result is exactly the ranking one
	thread would have produced, whatever the thread count. Both were
	previously pinned at min(cores, 8), which left most of a large machine
	idle on the keystroke path. Lower it to leave cores for something else;
	values above 64 are clamped.

					   *g:simplefinder_grep_cache*
g:simplefinder_grep_cache
	Whether grep may reuse the file list a recent walk produced instead of
	walking the tree itself. Default 1.

	Interactive grep sends one request per keystroke, and each of those
	re-walked the whole project -- every ignore file re-read, every
	directory stat-ed again -- before it could read a single file. The
	daemon already keeps that list for |:SimpleFinderFiles|, keyed on the
	same root, hidden/ignore toggles and path globs, so a grep with the same
	filters can read it; a grep that does have to walk publishes its own
	list in turn, and a walk cut short by cancellation or by the scan
	ceiling publishes nothing, since a partial tree must never be cached as
	a whole one.

	The list is at most 30 seconds old, so a file created while a panel is
	open is not searched until it expires. Set this to 0 to walk for every
	request, as versions before 0.5.0 always did.

					*g:simplefinder_include_globs*
g:simplefinder_include_globs
	List of ignore-style globs relative to the project root. When non-empty,
	only matching files are traversed by |:SimpleFinderFiles|, grep modes, and
	|:SimpleFinderSymbols|. Default [].

					*g:simplefinder_exclude_globs*
g:simplefinder_exclude_globs
	List of ignore-style globs to remove from the same daemon-backed sources.
	Default []. Keep the lists separate and do not prefix entries with !. >

	  let g:simplefinder_include_globs = ['*.rs', '*.toml']
	  let g:simplefinder_exclude_globs = ['*.generated.rs', 'fixtures/**']
<
	Filtering happens inside the Rust walker, before grep opens a file. At
	most 256 patterns are accepted and each may be at most 4096 UTF-8 bytes.
	A panel snapshots the lists when it opens; |:SimpleFinderResume| preserves
	that snapshot. Invalid syntax is shown as a panel error. Protocol-v3 path
	globs fail closed with an older daemon and ask you to rerun ./install.sh.
	Pure Vim sources and |:SimpleFinderGitFiles| are intentionally unchanged.

5. MAPPINGS                                            *simplefinder-mappings*

Nothing is mapped by default. Every command has a <Plug> target; map those
rather than the command names, so a command can grow an argument or a wrapper
without breaking your vimrc: >

  nmap <leader>ff <Plug>(simplefinder-files)
  nmap <leader>fg <Plug>(simplefinder-igrep)
  nmap <leader>fb <Plug>(simplefinder-buffers)
  nmap <leader>fw <Plug>(simplefinder-grep-word)
  nmap <leader>fr <Plug>(simplefinder-resume)
<
The full set: *simplefinder-plugs*
  <Plug>(simplefinder-files)       <Plug>(simplefinder-gitfiles)
  <Plug>(simplefinder-grep)        <Plug>(simplefinder-igrep)
  <Plug>(simplefinder-grep-word)   <Plug>(simplefinder-grep-visual)
  <Plug>(simplefinder-buffers)     <Plug>(simplefinder-recent)
  <Plug>(simplefinder-lines)       <Plug>(simplefinder-help)
  <Plug>(simplefinder-symbols)     <Plug>(simplefinder-marks)
  <Plug>(simplefinder-jumps)       <Plug>(simplefinder-quickfix)
  <Plug>(simplefinder-loclist)     <Plug>(simplefinder-resume)
  <Plug>(simplefinder-remote-workspaces)

                                        *<Plug>(simplefinder-grep-visual)*
Visual-mode grep is the exception, and the plugin ships the mapping: >

  xmap <leader>fg <Plug>(simplefinder-grep-visual)
<
Use it instead of writing your own. Grepping a selection has to happen while
Visual mode is still active, because Vim only writes the |'<| and |'>| marks
once the selection *ends* -- until then they still describe the previous one.
A hand-written mapping that reads the marks therefore searches one selection
behind, and finds nothing at all on the first selection of a session. The
<Plug> mapping is a |<Cmd>| mapping for exactly that reason: it never leaves
Visual mode, so the live region is still readable.

7. EXTENDING                                          *simplefinder-extending*

                                                          *simplefinder#Pick()*
simplefinder#Pick({spec})
        Open the panel on a list you supply. This is the whole extension
        surface: |:SimpleFinderMarks|, |:SimpleFinderJumps| and
        |:SimpleFinderQuickfix| are written against it, not beside it.

        {spec} keys:
          items   list of dictionaries, one per row (required)
          title   panel title (default "List")
          key     which field the fuzzy filter matches (default "display")
          Accept  Funcref called as Accept({item}, {openmode}) when a row is
                  chosen, where {openmode} is "edit", "split", "vsplit" or
                  "tabedit". It runs after the panel has closed and focus is
                  back in the window the panel was opened from.

        An item is a dictionary. `display` is the row text and the field the
        filter matches; when it is absent, `text` and then `path` are used, so
        a list of paths or of lines needs nothing else. The location fields
        `path`, `bufnr`, `lnum`, `col` and `text` are what make a row a place:
        with them and no Accept, <CR> opens it, the preview popup shows it,
        and <C-q>/<C-l> export it to the quickfix or location list -- all
        without a line of source-specific code.

        A colour-scheme picker, in full: >

          def ColorPicker()
            var items = mapnew(getcompletion('', 'color'),
              (_, name) => ({display: name}))
            simplefinder#Pick({
              title: 'Colorschemes',
              items: items,
              Accept: (item, _) => execute('colorscheme ' .. item.display),
            })
          enddef
<
        Rows keep their identity across filtering, so <Tab> multi-select and
        the quickfix export behave exactly as they do for the built-in
        sources. |:SimpleFinderResume| re-opens the same collection; it does
        not re-run whatever gathered it.

DAEMON SUPERVISION                                    *simplefinder-daemon*

The Rust daemon is managed by simplecore, the supervisor shared by the whole
simple* plugin suite. It is vendored into this repository at
autoload/simplefinder/core.vim; that file is generated, do not edit it in place.

What it guarantees:

- Liveness is always read from |job_status()|. job_start() returns a job
  object even when the exec itself failed, so a daemon that cannot start is
  never mistaken for one that is running.
- A superseded daemon's late exit callback cannot clear the state of the
  replacement that already took its place.
- Output still queued when you stop the daemon is discarded, so an explicit
  stop cannot be undone by an event that was already in flight.
- A daemon that dies is restarted automatically with exponential backoff.
  If it keeps crashing, the supervisor reports it once and stops trying
  rather than respawning forever; :SimpleFinderRestart re-arms it.
- Requests are correlated to replies by id and can time out, so a wedged
  daemon never leaves a callback hanging.

                                                      *:SimpleFinderHealth*
:SimpleFinderHealth
        Open the diagnosis in a scratch buffer -- it is meant to be read,
        scrolled and pasted into a bug report, none of which the message area
        does. Five sections, always present and always in this order, so two
        reports can be read side by side and a missing fact reads as one:

        ENVIRONMENT  Vim version, the features this plugin calls without a
                     guard (+job, +channel, +timers, +textprop, +popupwin),
                     and 'encoding'.
        BINARY       Which daemon was found, whether it is older than the
                     Rust sources next to it, and its version against the
                     version in the plugin's own Cargo.toml -- the upgrade
                     that pulls new Vim files over a stale lib/ binary shows
                     up here and nowhere else.
        CONFIG       |simplefinder#ValidateConfig()|, or one line saying every
                     option holds a value the plugin understands.
        RUNTIME      Daemon run state, negotiated protocol and capabilities,
                     uptime, crash and restart counts, and whether the
                     crash-loop breaker has tripped. Before the first search
                     there is no daemon yet and this says so, as information:
                     the daemon starts with the first search, and reporting
                     the expected state as an error sends every bug report
                     that quotes it down a blind alley.
        CONTEXT      Project root, the SimpleRemote workspace (its mode,
                     which engine searches it and where, a detached tree
                     root, the runtime and protocol in use, and whether the
                     SimpleRemote functions this plugin calls are present;
                     or why it is inactive), whether the workspace picker is
                     available, path glob counts, preview default.

        The daemon's version is asked for with |job_start()|, never
        |system()|: this is the command you run because something is wedged,
        and a synchronous probe of a wedged binary would hang it. The first
        report therefore says `probing…` on that line and rewrites itself in
        place when the answer arrives.

        A binary that never answers gets a verdict all the same, because that
        is the failure the command exists for: |job_start()| succeeds against
        a wedged binary and its exit callback simply never comes. The probe
        has a three-second deadline; when it expires the child is stopped and
        the line becomes `[ERROR] version: the binary did not answer
        --version within 3s`, redrawn in place like any other answer. Running
        :SimpleFinderHealth again after that tries once more, so a machine
        that was thrashing for one moment does not carry the red line for the
        rest of the session.

        The report gets a buffer of its own, created empty and only then
        named `SimpleFinderHealth`. It never adopts a buffer that name already
        resolved to, so a file of yours that happens to be called
        SimpleFinderHealth keeps its contents, its 'buftype' and its unsaved
        changes. If some other buffer already holds the name, the report stays
        unnamed rather than take it.

                                                      *:SimpleFinderRestart*
:SimpleFinderRestart
        Stop the daemon and start a fresh one. Clears the crash-loop breaker,
        so this is the way back after repeated failures.

                                                      *:SimpleFinderLog*
:SimpleFinderLog
        Open the daemon transcript in a scratch buffer: start and exit events,
        restarts, protocol handshakes, send failures and stderr.

                                              *g:simplefinder_symbol_keywords*
g:simplefinder_symbol_keywords
        Dictionary of filetype to the list of keywords that introduce a
        definition, used by |:SimpleFinderSymbols|. An entry replaces the
        built-in set for that filetype. Default {}. >
            let g:simplefinder_symbol_keywords = {'zig': ['fn', 'const']}
<
                                         *g:simplefinder_symbol_all_languages*
g:simplefinder_symbol_all_languages
        Search every language's keywords regardless of the current filetype.
        Default 0.

DAEMON COMMAND LINE                                  *simplefinder-daemon-cli*

The daemon takes no arguments in normal use: the plugin starts it and speaks
JSON over its stdin and stdout.  For diagnosis it also answers: >

  simplefinder-daemon --version
  simplefinder-daemon --help
  simplefinder-daemon --self-test
<
--self-test checks the handshake reply serialises and prints "ok".
install.sh runs it on the freshly built binary before replacing a working one,
so a build that compiles but does not work never reaches lib/.

Every daemon in the simple* suite answers these three the same way.

VENDORED SUPERVISOR                                  *simplefinder-simplecore*

The daemon supervisor in autoload/simplefinder/core.vim, and the test harness
beside it, are vendored from the suite's shared .simplecore bundle rather
than written here — each plugin carries its own copy so that installing
this plugin alone is enough.  Do not edit those files in place: >

  make core-verify
<
checks each of them against the sha256 recorded in .simplecore.manifest and
fails the build when one has drifted.  `make check` depends on it.

The bundle lives at https://github.com/beamiter/simplecore.  To change the
supervisor, clone it beside the plugins, edit it there, and re-vendor: >

  git clone https://github.com/beamiter/simplecore ../.simplecore
  ../.simplecore/vendor.sh
<
